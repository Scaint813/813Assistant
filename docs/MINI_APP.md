# Telegram Mini App

Mini App — основной визуальный интерфейс 813Assistant. Постоянная кнопка
`Управление` настраивается через Telegram Bot API при запуске процесса, а нижняя
навигация внутри приложения всегда показывает пять независимых разделов: день,
планнер, задачи, здоровье и профиль. Ошибка или пустой результат одного источника
не блокирует переходы и загрузку остальных разделов.

Вход в защищённый интерфейс выполняется именно нативной menu button возле поля
ввода. Reply-клавиатура остаётся для текстовых фраз: Telegram не гарантирует
авторизационный `initData` для Mini App, запущенного из `KeyboardButton`.

Подробные инструкции не занимают ежедневные экраны. Они собраны в отдельном
разделе `Справка`, доступном из верхней панели и профиля. Карточка подключения
показывает только состояние, одно основное действие и защищённые URL/token в
отдельном bottom sheet.

Frontend работает без сборщика и разделён по ответственности:

- `app.mjs` — навигация, события и жизненный цикл;
- `api_client.mjs` — авторизованные запросы и таймауты;
- `resource_store.mjs` — независимый stale-while-refresh кэш разделов;
- `views.mjs` — чистое представление данных;
- `formatters.mjs` — безопасный HTML и локальные дата/время;
- `faq.mjs` — справочный контент.

## Конфигурация

```dotenv
MINI_APP_ENABLED=true
MINI_APP_PUBLIC_URL=https://assistant.example.com/assistant/
MINI_APP_HOST=127.0.0.1
MINI_APP_PORT=8782
```

Публичный URL обязан использовать HTTPS и завершаться `/`: frontend обращается
к API относительными путями. Локальный порт не нужно публиковать напрямую.

Пример location для nginx:

```nginx
location = /assistant {
    return 301 /assistant/;
}

location /assistant/ {
    proxy_pass http://127.0.0.1:8782/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # Telegram Web открывает Mini App во frame. Не наследуем серверный
    # X-Frame-Options: SAMEORIGIN; допустимые origins заданы приложением в CSP.
    add_header X-Content-Type-Options nosniff always;
    add_header Referrer-Policy no-referrer always;
}
```

После изменения проверяются конфигурация и публичный endpoint:

```bash
sudo nginx -t
sudo systemctl reload nginx
curl -fsS https://assistant.example.com/assistant/healthz
```

## Модель безопасности

- Данные API недоступны без заголовка `Authorization: tma <initData>`.
- Сервер проверяет HMAC-подпись Telegram, `auth_date` и allowlist пользователя.
- `initDataUnsafe` не используется как источник доверенных данных.
- Ответы API имеют `Cache-Control: no-store`; статические ответы получают CSP,
  `nosniff`, запрет внешних форм и ограничение Telegram origins для frame.
- Импорт календаря ограничен 5 МБ и меняет только события источника `hse_ical`
  конкретного пользователя.
- Отдельный endpoint автоматизации iPhone принимает только календарь с точным
  именем `HSE`, принудительно записывает источник `hse_ios` и защищён отдельным
  `CALENDAR_BRIDGE_TOKEN` длиной не менее 32 символов. Токен выдаётся только
  владельцу через подписанную сессию Mini App.

`X-Debug-User` работает только у экземпляра сервера, созданного с явным
`dev_mode=True`; production-процесс этот режим не включает.

## HSE App и календарь iPhone

HSE App не предоставляет `.ics` или серверную ссылку. После включения
«Синхронизации с Календарём» он создаёт в iCloud системный календарь `HSE` и
обновляет его при входе в приложение. Mini App показывает владельцу статус и
защищённые данные подключения; пошаговая инструкция находится в `Справке`.

Автоматизация запускается при закрытии HSE App, выбирает только события
календаря `HSE` на 14 дней и отправляет зеркало на сервер. Перед заменой сервер
проверяет целостность снимка. Пустой снимок при наличии будущих занятий, одно
далёкое событие и резкое уменьшение числа занятий помечаются как неполные и не
затирают последнюю надёжную версию. Если надёжной версии ещё не было, такой
снимок остаётся в диагностике, но не показывается как расписание. Личные
календари и события других источников не меняются. После полноценного снимка план пересчитывается сразу; кроме этого,
план каждого пользователя пересобирается при старте, каждые четыре часа и
ежедневно в 06:45 его часового пояса. При смене часового пояса cron-задачи
перерегистрируются без перезапуска процесса.
Пошаговая настройка:
[`HSE_IPHONE_SHORTCUT.md`](HSE_IPHONE_SHORTCUT.md).

## Контур ассистента

Экран `Сегодня` — командный центр, а не копия календаря. Он независимо собирает:

- `Сейчас` и `Дальше` из календаря, тренировок и рабочих блоков;
- состояние восстановления из последнего Health snapshot;
- риски конфликтов, просрочек и неполного внешнего расписания;
- до четырёх текущих приоритетов.

План пересчитывается после создания/изменения задачи, изменения профиля,
полноценной синхронизации HSE, при старте, фоновом reconcile и утренним заданием.
Просмотр экрана ничего не изменяет; фронтенд обновляет данные при возвращении в
приложение и раз в 90 секунд, пока он открыт.

## Поведение задач

Завершение задачи — смена статуса, а не удаление. Она остаётся в разделе
`Завершено сегодня`, где доступно действие `Вернуть`. Временной блок завершённой
задачи больше не показывается как предстоящее дело. Изменить задачу другого
пользователя невозможно: все запросы фильтруются одновременно по `task_id` и
проверенному `user_id`.
