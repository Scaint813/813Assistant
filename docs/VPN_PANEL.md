# «Мой VPN» в 813Assistant

Панель открывается через `Профиль → Подключения → Мой VPN`. Она доступна
только владельцу `ALLOWED_USER_ID`, включая случаи, когда ассистентом пользуются
другие разрешённые пользователи. Endpoint `GET /api/v1/vpn` использует ту же
подписанную Telegram-авторизацию, что и остальной Mini App, с дополнительной
проверкой владельца. Все ответы API запрещают кэширование в HTTP.

## Что показывает панель

Три состояния проверяются независимо:

1. **Tailscale на сервере.** Фиксированная команда `tailscale status --json`
   проверяет локальный экземпляр Tailscale на машине Mini App. Состояния
   `Stopped`, `NeedsLogin`, `Starting`/`NoState`, недоступный CLI и ошибка
   проверки не подменяются зелёным статусом. Таймаут ограничен; результаты
   серверной проверки кэшируются на десять секунд, включая одновременные
   запросы. Полный JSON и stderr CLI пользователю не возвращаются.
2. **Устройства.** Из CLI выбираются только адреса из `VPN_DEVICE_IPS`.
   Доступность Mac в Tailscale не подтверждает, что весь его интернет идёт
   через Exit Node. Без локального помощника это состояние остаётся
   неизвестным. Сон устройства также не равен неисправности VPN.
3. **Маршрут этого запроса.** Сервер сопоставляет достоверно определённый
   публичный адрес входящего запроса с настроенным адресом VPS. Адрес
   вычисляется для каждого запроса, отдельно от кэша серверного CLI.
   Проверяется именно устройство, на котором открыт Mini App. Панель на
   телефоне не проверяет интернет другого Mac. Один запрос подтверждает
   только своё семейство IP, а не одновременно IPv4 и IPv6.

Кнопка проверки принудительно запрашивает API. Старые данные при обновлении,
ошибке сети или возвращении в приложение не являются новой проверкой.
В интерфейсе указано время результата; неизвестное состояние не означает
«выключено» или «защищено».

Страна задаётся оператором и подписана как настройка, а не результат живой
геолокации. Панель не проверяет договор хостинга и никогда не утверждает,
что адрес закреплён за сервером навсегда. В наблюдавшейся конфигурации адрес
`89.22.228.86` определялся как Финляндия (`FI`), не Швеция. IP нельзя сделать
шведским одним изменением подписи в настройках.

## Включение

Сначала разверните код обычным способом проекта. В серверном `.env` задайте:

```dotenv
VPN_PANEL_ENABLED=true
VPN_EXIT_NODE_NAME=economic-peach
VPN_EXPECTED_IPV4=89.22.228.86
VPN_EXPECTED_IPV6=2a0b:4140:5020::2
VPN_DEVICE_IPS=100.124.44.54
VPN_COUNTRY_CODE=FI
```

После изменения окружения нужен перезапуск только `813assistant`, не
`tailscaled` и не остальных ботов. Таблицы БД и миграции для панели не меняются.
Службе нужен только доступ к чтению `tailscale status --json`. Не выдавайте
ассистенту общий `sudo`, root-ключ или Tailscale API token ради этой панели.
Если процесс Mini App запущен на другой машине или в контейнере без доступа
к Tailscale хоста, панель не сможет проверить нужный сервер: покажет
недоступность/неизвестное состояние. Не подменяйте это статическим «работает».

По умолчанию `VPN_PANEL_ENABLED=false`. Владелец видит раздел с предложением
настройки; CLI не запускается. Ошибка VPN не должна блокировать задачи,
здоровье и другие независимые разделы Mini App.

Неверные IP/CIDR/имя заголовка отключают только эту необязательную интеграцию:
причина отмечается в журнале, остальные функции ассистента продолжают запуск.

## Достоверный IP за прокси

По умолчанию `X-Forwarded-For`, `X-Real-IP`, `CF-Connecting-IP` игнорируются.
Если Mini App доступен через localhost-прокси, адрес `127.0.0.1` не считается
публичным адресом устройства: маршрут показывается как неизвестный.

Для доверенного nginx на этой же машине можно задать:

```dotenv
VPN_CLIENT_IP_HEADER=X-Forwarded-For
VPN_TRUSTED_PROXY_CIDRS=127.0.0.1/32,::1/128
```

nginx обязан устанавливать/дополнять заголовок на основании адреса реально
подключившегося клиента, например существующей настройкой
`proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`. Приложение
проверяет транспортный адрес прокси, затем разбирает цепочку справа налево,
удаляя только явно доверенные узлы. Подставленный пользователем адрес в
начале цепочки не становится доказательством VPN.

Для Cloudflare Tunnel допустим `VPN_CLIENT_IP_HEADER=CF-Connecting-IP`,
только если входящий трафик действительно проходит через проверенный
cloudflared и origin недоступен в обход этого ingress. В доверенные CIDR
включается фактический транспортный адрес cloudflared, например loopback.
Не включайте этот режим для nginx, который просто пропускает пользовательский
`CF-Connecting-IP` из интернета без проверки Cloudflare.

При нескольких прокси настройте всю реальную доверенную цепочку. Не доверяйте
`0.0.0.0/0`, `::/0` или всем внутренним сетям ради зелёного индикатора.
Неверная конфигурация прокси может показать адрес промежуточного сервера
вместо устройства. Проверку делают реальным запросом из Telegram с включённым
и выключенным Exit Node; подмена произвольного HTTP-заголовка не является
допустимым тестом маршрута.

## Границы управления

Панель только читает состояние. Она не запускает shell-команды из запроса,
не меняет маршруты, не перезапускает VPN и не управляет firewall.
В браузере/Telegram WebView нет системных прав для переключения VPN на Mac.
Поэтому фиктивных кнопок «Включить / Выключить VPN» здесь нет: подключение
переключается в штатном Tailscale. Для удалённого переключения потребуется
отдельный установленный локальный помощник с узким набором разрешённых действий.

Панель не является внешним мониторингом: выключенный VPS не сможет сам
отправить Telegram-уведомление. Для таких оповещений нужен отдельный
независимый проверяющий сервис. Постоянные фоновые проверки IP Mac также
требуют локального помощника; закрытый Mini App этого не делает.

Работа туннеля, страна адреса и разрешение пользоваться сторонним сервисом —
разные проверки. Панель не обещает доступ к Claude, не проверяет статус
аккаунта Anthropic и не подтверждает соблюдение условий сервиса.

## Приёмка

- Открыть раздел подписанной сессией владельца. Другому разрешённому
  пользователю endpoint возвращает 403, без авторизации — 401.
- Проверить, что выключенная интеграция, отсутствующий CLI и `NoState`
  не отображаются как подтверждённый рабочий VPN.
- Подтвердить IP за реальным ingress. Проверить, что запрос с поддельным
  forwarded-заголовком от недоверенного клиента не получает `via_vps`.
- Открыть Mini App на Mac и телефоне по отдельности: результаты относятся
  к соответствующему устройству. Проверить явно указанное семейство IP.
- Отключить сеть при открытой панели: старый результат должен быть помечен
  как требующий новой проверки. Остальные пять разделов сохраняют навигацию.
- Проверить кнопки обновления, возврат в профиль и короткую русскую инструкцию
  на мобильном экране. После выкладки закрыть/открыть Mini App, чтобы
  Telegram загрузил обновлённые версии статических файлов.
